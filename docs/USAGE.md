# 使用说明

面向日常编辑与站点管理。部署与环境变量见 [DEPLOY.md](./DEPLOY.md)。

## 登录

打开站点根路径或 `/sign-in`。

支持的方式（取决于管理员是否配置）：

- **邮箱 + 密码**（首次 `/setup` 创建的管理员账号）
- **GitHub**（已配置 GitHub App 时）
- **协作邀请 OTP**（被邀请到某仓库的协作者）

登录后可进入仓库列表或（本地模式下）直接进入本地项目。

## 选择仓库 / 本地项目

### GitHub 仓库

1. 安装 GitHub App 到目标账号 / 组织
2. 在首页选择有权限的仓库与分支
3. URL 形如：`/{owner}/{repo}/{branch}/...`

### 本地磁盘项目

开启 `LOCAL_REPO_MODE` 后：

1. 在仓库菜单中 **选择本地项目目录**
2. 目录需存在且可写（可选任意本机路径；仅当配置了 `LOCAL_REPO_ALLOWED_ROOTS` 时才限制范围）
3. 保存内容会直接写入磁盘；仍可通过「发布」等流程对接远端（视配置而定）

## 主要功能

### 内容集合

侧边栏进入各内容类型（文章、页面、自定义集合等）：

- 列表浏览、新建、编辑、删除
- 支持 Frontmatter + Markdown / 富文本等字段（由 CMS 配置决定）
- 部分模板（如 source-files）为固定文件列表，操作列可能受限

### 媒体库

上传与管理图片等静态资源；路径必须在配置的 media 根目录内。

### 菜单 / 内容页设置

路径一般为：`/{owner}/{repo}/{branch}/nav-menu` 或侧边栏「菜单设置」。

- 配置侧边栏显示项、图标
- 管理内容页模板与分组
- **自动保存**（约 600ms 防抖）；冲突时会合并远程变更并重试

### 站点设置

主题、站点级选项等（视仓库配置）。

### 待发布变更

对 GitHub 暂存模式：编辑先写入暂存区，在「变更」页集中查看、丢弃或发布到仓库。

### 评论 / 分析 / WebDAV 等

在对应设置页配置外部服务地址；服务端会对出站 URL 做安全校验。

### 外观

**设置 → 外观**：

- **玻璃效果（透明背景）默认关闭**
- 关闭时可选浅色 / 深色
- 开启玻璃效果时固定深色

偏好保存在浏览器 `localStorage`（键名 `pagescms-glass`）。

## 协作

管理员可邀请协作者（邮箱）：

1. 发送邀请链接 / OTP
2. 协作者登录后获得对应仓库的编辑权限（具体写权限取决于安装令牌与策略）

## 管理员

具备管理员邮箱（`/setup` 或部署配置中的 admin emails）的用户可：

- 修改部署配置（站点 URL、GitHub App、邮件等）
- 管理登录背景图等全局设置
- 访问 `/admin`（用户检索等）

## 常用路径速查

| 路径 | 说明 |
|------|------|
| `/sign-in` | 登录 |
| `/setup` | 首次初始化（完成后勿对外暴露抢注窗口） |
| `/` | 首页 / 仓库列表 |
| `/{owner}/{repo}/{branch}` | 仓库首页 |
| `/{owner}/{repo}/{branch}/collection/{name}` | 集合列表 |
| `/{owner}/{repo}/{branch}/media/{name}` | 媒体 |
| `/{owner}/{repo}/{branch}/changes` | 待发布变更 |
| `/{owner}/{repo}/{branch}/settings` | 仓库设置 |
| `/settings` | 账户 / 部署相关设置 |

## 建议工作流

1. 从集合新建或打开条目 → 编辑 → 保存  
2. GitHub 模式：在「变更」中确认 diff → 发布  
3. 本地模式：文件已在磁盘；用 Hugo / 其它工具自行构建预览  
4. 结构调整（菜单、模板）在菜单设置中完成，等待自动保存成功提示  

## 常见问题

**保存失败 / 配置冲突**  
刷新后重试；菜单设置会自动合并冲突并有限次重试。

**打不开某些路径下的文件**  
敏感路径（如 `.env`、`.git`、密钥类文件名）被系统拦截，属安全设计。

**登录页背景**  
管理员可在设置中更换图床 URL（仅 http/https）。

**需要重置整个初始化**  
仅运维场景：见 [DEPLOY.md](./DEPLOY.md) 中的 `reset-app-config` 说明；会清除 `app_config`，请谨慎。
